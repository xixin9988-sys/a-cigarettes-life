# 桌面版构建与分发指南

> 适用项目：本项目（A Cigarette's Life，Vite + Phaser 前端，IndexedDB 存档）
> 目标：Windows 双击即玩、玩家电脑不需要装 Node.js、不上架 Steam、尽量不动游戏本体代码
> 实测环境：Electron 38.8.6 / Chromium 140 / Windows 10+ / 显示缩放 150%

---

## 0. 先看命令

```
npm run desktop:dev        # 开发调试：先 npm run dev 起 vite(3000)，再执行这个
npm run desktop:start      # 本机验收：直接读 dist/，等价于打包后玩家看到的样子
npm run desktop:pack       # 只产出免安装目录 release/win-unpacked/（最快的验证方式）
npm run desktop:portable   # 产出单文件绿色版 exe
npm run desktop:release    # 产出 绿色版 + 安装包
```

发布前只需要记住一条链路：`npm run desktop:release` → 打开 `release\` → 把 exe 发给别人。

## 2. 三个必须做的设计决定

### 2.1 为什么不能 `loadFile('dist/index.html')`

你的构建里有：

- `dist\assets\index-*.js`：2.7 MB 的 ES module
- `dist\assets\simulation.worker-*.js`：module worker（`new Worker(url, { type: 'module' })`）

在 `file://` 下，模块 worker 与部分存储 API 会被 origin 规则挡掉，直接白屏或世界不推进。
所以继续「本地起服务 + 用 http 页面加载」是改动最小的路线——这与你现在的 `vite dev` 行为完全一致。

实测：Electron 里这套 dist 能正常启动、Phaser 正常 boot、WebGL 正常、module worker 正常加载。

### 2.2 端口 0 的陷阱：IndexedDB 存档是按 origin 存的（**本次最关键的一条**）

`http://127.0.0.1:58156` 和 `http://127.0.0.1:58304` 是**两个不同的 origin**。
IndexedDB、localStorage、CacheStorage 全部按 origin 隔离。

你的存档都在 IndexedDB 里（`src/persistence/IndexedDBStorage.ts`，库名 `a_cigarettes_life`）。
如果窗口直接加载 `http://127.0.0.1:<每次随机的端口>/`，玩家每次启动都会看到一个**空的存档列表**——
数据没丢，只是换了个 origin，看不见了。

实测（同一台机器，连续两次启动）：

| 模式 | 第一次 origin | 第二次 origin | 第二次能否读到第一次写的存档 |
|---|---|---|---|
| 直接 http://127.0.0.1:随机端口 | http://127.0.0.1:58156 | http://127.0.0.1:58304 | **读不到** |
| 固定 origin（本方案默认） | app://game | app://game | **能读到** |

**解决方式（已实现，默认开启）：**

1. 静态服务器照旧监听 `127.0.0.1` + 端口 `0`（由系统分配，永不冲突）；
2. 窗口加载的是 `app://game/index.html`——一个注册为 standard+secure 的自定义协议；
3. `protocol.handle('app', ...)` 内部用**同一份磁盘文件**返回响应（和 HTTP 服务器共用
   `createFileResponse()`，不是代理转发，少一跳、少一堆 header 问题）。

这样 origin 恒为 `app://game`，端口怎么变都无所谓。

实测（端口 50812 → 50986 两次启动）：`app://game` 下写入的 IndexedDB 标记，第二次启动仍在。

> 想回到纯 http 模式：设环境变量 `ACS_ORIGIN_MODE=http`。
> 此时**务必同时固定端口**（`ACS_PORT=52111`），否则就是上面那行「读不到」。
> 为什么还留着 HTTP 服务器？① 便于在浏览器里打开同一份构建排查；② 便于将来加调试工具；
> ③ 你原本的心智模型就是「有个本地服务」。

### 2.3 资源目录：开发期 vs 打包后

| 场景 | `app.getAppPath()` | 游戏实际位置 | `app.isPackaged` |
|---|---|---|---|
| `npm run desktop:start` | `<repo>` | `<repo>\dist` | false |
| 打包后 exe | ...\resources\app.asar | ...\resources\app.asar\dist | true |

`resolveGameRoot()` 把两种情况都覆盖了，并且**先检查 index.html 是否存在**；
找不到就弹系统错误框提示「先跑 npm run build」，而不是给玩家一个白屏。

asar 内的文件用 `fs` 读是透明的（Electron 给 fs 打了补丁），**不需要** `asarUnpack`。

## 3. 代码要点（按启动顺序）

完整代码在 `desktop\electron\` 下，这里只讲为什么这么写。

### 3.1 主进程启动顺序（main.cjs）

1. `app.setName("A Cigarette's Life")` → 决定 `%APPDATA%\A Cigarette's Life\` 这个存档目录名
2. `requestSingleInstanceLock()` → 玩家双击两次不会开出两个窗口 / 两个服务器
3. `protocol.registerSchemesAsPrivileged`（必须在 ready 之前）
4. 起静态服务器 → 得到 `{ port, origin }`
5. `protocol.handle('app', ...)` → 从磁盘读同一份文件
6. 建 `BrowserWindow`（1280×720 / `autoHideMenuBar` / `contextIsolation` / `sandbox`）
7. `loadURL('app://game/index.html')`

### 3.2 端口 0 与首选端口

```
server.listen({ host: '127.0.0.1', port: preferredPort || 0, exclusive: true })
```

- 默认 `port 0`：操作系统分配一个空闲端口，永远不会「端口被占用」；
- 若显式给了 `ACS_PORT` 且被占用，自动退回端口 0 并打日志，不会卡死。

### 3.3 窗口

```
new BrowserWindow({
  width: 1280, height: 720, minWidth: 960, minHeight: 540,
  autoHideMenuBar: true,        // 你要求的：菜单栏不占地方，Alt 才出现
  backgroundColor: '#1a1a1f',   // 和 index.html 的底色一致，避免白闪
  show: false,                  // 等 ready-to-show 再显示
  webPreferences: {
    preload: path.join(__dirname, 'preload.cjs'),
    contextIsolation: true,     // 游戏代码拿不到 Node
    nodeIntegration: false,
    sandbox: true,
    webviewTag: false,
  },
})
```

- `F11` 全屏切换（在 `before-input-event` 里处理，不依赖菜单）；
- `F12` 只在**未打包**时可用，打包后不响应，也不会自动打开 DevTools；
- `will-navigate` / `setWindowOpenHandler` 把游戏锁在本 origin，外链交给系统浏览器；
- 窗口位置大小记在 `%APPDATA%\A Cigarette's Life\desktop-settings.json`，且会校验是否还在可见显示器上。

### 3.4 preload（contextIsolation 下的安全桥）

```
contextBridge.exposeInMainWorld('acsDesktop', {
  isDesktop: true,
  baseUrl: 'app://game/index.html',   // 游戏实际用的地址
  port: 50812,                        // 本地服务端口（调试用）
  toggleFullscreen(), quit(), ...
});
contextBridge.exposeInMainWorld('gameBaseUrl', baseUrl);
```

只暴露普通数据和两个「发完就忘」的通道，不透出 `ipcRenderer`、不透出 `require`。

### 3.5 关闭窗口前必须手动存档

游戏自己写了 `window.addEventListener('beforeunload', () => { void game.saveGame(...) })`，
但那是**异步**的 IndexedDB 写入，窗口一销毁就没了。

所以主进程在 `close` 事件里 `preventDefault()`，先执行：

```
var game = window.__A_CIGARETTES_LIFE__.game;
return game.saveGame(game.getSaveManager().getCurrentSlotId());
```

等它 resolve（最多 4 秒兜底）再 `win.destroy()`。**游戏本体代码一行都不用改。**

## 4. package.json 的改动（共 3 处）

```
{
  "main": "desktop/electron/main.cjs",          // ① 入口
  "scripts": {                                   // ② 5 条桌面脚本
    "desktop:dev": "electron . --dev-server=http://127.0.0.1:3000",
    "desktop:start": "electron .",
    "desktop:pack": "npm run build && electron-builder --win --dir --config desktop/electron-builder.yml",
    "desktop:portable": "npm run build && electron-builder --win portable --config desktop/electron-builder.yml",
    "desktop:release": "npm run build && electron-builder --win --config desktop/electron-builder.yml"
  },
  "devDependencies": {                           // ③ 两个开发依赖
    "electron": "^38.8.6",
    "electron-builder": "^26.18.0"
  }
}
```

两个要点：

- **`--config desktop/electron-builder.yml` 不能省**。electron-builder 只会在**项目根目录**自动找
  `electron-builder.yml`；配置文件放进 `desktop/` 之后必须显式指定，否则它会用默认配置
  （产物进 `dist\`、把整个 node_modules 打进 asar，实测 asar 从 3.6 MB 变成 157 MB）。
- `"type": "module"` 保留不动：Electron 外壳用 `.cjs` 扩展名强制 CommonJS，互不干扰。

## 5. 打包产物与「隐藏终端窗口」的澄清

### 5.1 两种产物

| 目标 | 产物 | 玩家体验 | 适合 |
|---|---|---|---|
| `portable` | `A Cigarette's Life-1.0.0-portable.exe` | 双击即玩，不解压目录 | 发给朋友、免安装、U 盘 |
| `nsis` | `A Cigarette's Life-1.0.0-setup.exe` | 走安装向导，生成桌面/开始菜单快捷方式 | 正式分发 |

两个都是 64 位；`--dir` 产出的 `release\win-unpacked\` 是免安装目录，最适合本机快速验证。

### 5.2 关于「子系统设为 windows 以隐藏终端」

**Electron 打出来的 exe 本来就是 Windows GUI 子系统**，双击不会弹黑框，不需要额外设置。
`electron-builder` 也没有 `win.subsystem` 这个选项——那个写法属于 `pkg` / `nexe` / `.NET` 这类
「把 Node 脚本塞进 exe」的工具。你看到的教程大概率是那一路。

真正会看到黑框的两种情况：

1. 开发期 `npm run desktop:start`（从终端启动 electron，终端就是它的父窗口）；
2. 你将来在代码里 `spawn` 子进程时忘了 `windowsHide: true`。

### 5.3 `files` 白名单（体积关键）

```
files:
  - dist/**/*
  - desktop/electron/**/*
  - package.json
  - '!**/node_modules/**/*'
```

外壳只用 Node 内置模块，Phaser 早已被 Vite 打进 `dist/assets`，
所以 `node_modules` 全部排除——否则会把 400 MB 的开发依赖一起塞进安装包。

## 7. 硬编码 `localhost:3000` 的排查与替换

### 7.1 先扫描

```
# 只看游戏源码（排除 node_modules / dist）
rg -n "127\.0\.0\.1|localhost|:3000" src public index.html
```

**本项目实测结果：`src\` 下 0 处**（命中的 `30000` 全是金额/时长数值）。
也就是说：换端口不会破坏现有代码，这一节属于「以后加了东西再回来看」的保险。

### 7.2 真要写地址时的三层回退

优先级从高到低，**能不写死就不写死**：

```
// src/core/net/base-url.ts —— 如果将来需要绝对地址，用这个函数，不要各写各的
export function getBaseUrl(): string {
  // 1) Electron 外壳注入的真实地址（preload 已经暴露）
  const desktop = (window as any).acsDesktop;
  if (desktop?.baseUrl) return new URL('.', desktop.baseUrl).href;

  // 2) 普通浏览器：相对路径优先，永远跟着当前 origin 走
  if (location.protocol === 'http:' || location.protocol === 'https:') {
    return new URL('.', location.href).href;
  }

  // 3) 兜底：本地开发约定
  return 'http://127.0.0.1:3000/';
}
```

用法：`fetch(getBaseUrl() + 'assets/x.json')`。
更推荐的做法是**干脆用相对路径**（`'./assets/x.json'`），这样三种环境都不用改。

## 8. 后端 / WebSocket / 存档路径

### 8.1 现状（已核对源码）

- `src\` 下**没有** `fetch` / `XMLHttpRequest` / `WebSocket` 调用；
- 唯一的"后台"是 **module worker**（`simulation.worker.ts`），实测在 `app://` 下正常加载；
- 主菜单也写着 `deterministic seeded world · no network`。

所以本次打包**不涉及网络**，离线可玩。

### 8.2 将来若要加后端

1. **别监听 `0.0.0.0`**：用 `127.0.0.1` + 端口 0，把实际端口通过 preload 传给前端；
2. **启动顺序**：先起后端 → 健康检查通过 → 再 `loadURL`，否则首屏就报错；
3. **CORS**：页面 origin 是 `app://game`，后端要显式允许这个 origin（或在主进程用
   `net.fetch` 转发，把跨域留在主进程里）；
4. **WebSocket**：`ws://127.0.0.1:<port>` 一般可用，但混合内容规则对自定义协议要求
   `secure: true`（已注册）——别忘了 `Content-Security-Policy` 里加 `connect-src`；
5. **打包**：后端如果是独立 exe，用 `extraResources` 放进去，主进程
   `spawn(path.join(process.resourcesPath, 'server.exe'), [], { windowsHide: true })`，
   并在 `before-quit` 里 kill 掉，避免僵尸进程。

### 8.3 存档路径

| 内容 | 位置 |
|---|---|
| IndexedDB（存档本体） | `%APPDATA%\A Cigarette's Life\IndexedDB\app_game_0.indexeddb.leveldb\` |
| GPU / 缓存 | `...\Cache`、`...\GPUCache`（可删，不影响存档） |
| 窗口状态 | `...\desktop-settings.json` |

- **备份/迁移**：整个 `%APPDATA%\A Cigarette's Life\` 文件夹复制走即可；
- **卸载**：NSIS 安装包默认**不删** `%APPDATA%`（`deleteAppDataOnUninstall: false`），重装后进度还在；
- **绿色版**（数据跟着 exe 走）：启动时加 `ACS_PORTABLE_DATA=1`，会把 userData 改到
  `PORTABLE_EXECUTABLE_DIR\data`（portable 目标才有这个变量）。注意：切换模式等于换存档位置。

## 9. 已知坑

1. **`ELECTRON_RUN_AS_NODE=1`**（本机就开着）：被这个环境变量污染时，打包后的 exe 会以
   Node 模式启动并立刻退出/报 `Cannot read properties of undefined`。
   排查：启动前检查该变量，玩家机器一般不会有（某些开发工具会设置）。
2. **SmartScreen「未知发布者」**：不签名必然出现。朋友点「更多信息 → 仍要运行」即可；
   正式分发建议买代码签名证书（OV/EV）。
3. **杀软误报**：未签名的 Electron 自解压包常被误判。签名 + 提高版本号重传可缓解。
4. **首次白屏**：九成是 `dist\` 没构建或路径不对，看 `resolveGameRoot()` 的候选路径。
5. **窗口比屏幕还大**：150% 缩放下 1280×720 逻辑像素 = 1920×1080 物理像素。要按物理像素算，
   可以给 `BrowserWindow` 传 `useContentSize: true` 或按 `screen.getPrimaryDisplay().workAreaSize` 限幅。
6. **`console-message` 等 API 签名变了**：Electron 35+ 用事件对象，老教程的
   `(event, level, message)` 已废弃（只影响调试代码，不影响游戏）。
7. **不要用 `npm run desktop:start` 截图当验收**：开发期没有 asar、没有图标、没有加速缓存，
   正式验收一律用 `desktop:pack` 出来的 `release\win-unpacked\*.exe`。
